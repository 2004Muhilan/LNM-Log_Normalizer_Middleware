# P8 test-coverage audit — what each check exercises against what its name implies

**Why this exists.** Four times in this project a test passed without testing: P4's corpus differential
compared presence and never values; the container test stage had not run since P5; `udp_datagram` sat
outside its schema enum because the emitting side was never validated; and Go's test cache reported
`ok (cached)` for a golden vector it no longer accepted, because the goldens live outside the module.
Four is a pattern. This audit reads every check script and the tests behind it and names **every
assertion that can pass without testing anything**: statuses lost in pipelines, comparisons of presence
rather than value, stages that skip silently, negative tests satisfied by the wrong failure, goldens
regenerated by the script that then checks them, artifacts built once and never rebuilt.

**Method.** Three independent read-only sweeps (P1–P3 scripts; P4–P6; P7, the demo and the container
stage), each tracing script → invoked test → asserted condition with file and line; then every finding
acted on below was re-verified by hand, and the most serious by experiment. Sweeps ran 2026-09-20 against
`579d9bc`. **Fixed in P8** means the change is in this commit and the check now fails where it used to
pass; **Open** means it is recorded here and not fixed — by decision, for time, or because the fix
touches a contract or a settled decision and is the team's call.

**Second pass (2026-09-20, later the same day).** The three findings this document named as the ones to close
first are closed — §3.1 (goldens regenerated by the checks that read them), §3.4 (corpus replay compared no
extracted value), §3.6 (the answering model never checked) — and two more of the same family turned up while
closing other things: the learning image's readiness wait grepped for a string the server never prints (so it
always ran to its timeout and the P4 build script, which had no failure branch, could not notice), and
`learning/Dockerfile` copied `keys/` whole, baking the dev **private** keys into the P4 image. Status lines
below are updated in place; everything still marked Open is open.

## 1. The fifth one: a verifier that failed open

The most serious finding is not a test defect but what a vacuous test had been hiding.
`checkpoint.VerifyBundle` returned `(findings, nil)` on three paths — checkpoint signature file missing,
daily root or its signature missing, daily root unparseable — and `ulpf-verify bundle` failed only on a
non-nil error. **Delete `checkpoint.json.sig` from an exported bundle and the external witness printed
`FINDING checkpoint: signature file missing` followed by `VERIFY: OK … signed by a trusted authority`,
exit 0.** The demo's step 6 and the P7 demo both `grep "VERIFY: OK"`.

It went unseen because the only negative tests for the trust path were vacuous: `p5-witness-test.sh`
step 5 ("unknown authority refused") and `TestExportBundleVerifiesWithOnlyTheTrustStore` both ran on the
bundle the previous step had already tampered, so the leftover `event.raw` finding satisfied them — they
would have passed with the trust store ignored entirely — and the script pointed `--trust` at a path
that did not exist, with output discarded, so a mount error passed too.

*Fixed in P8:* the three returns are errors; `ulpf-verify bundle` fails on any finding; the Go test and
the script verify an **untampered** bundle against an empty trust store and require the refusal to be
*for the missing authority and nothing else*; both add the missing-signature case; the script refuses to
run against a stale `ulpf-verify` image if the build fails. `p8-check.sh` requires all three `ok` lines.

## 3. Patterns, with what remains open

**3.1 Goldens regenerated by the check that reads them (Fixed in the second pass).**
`build_vectors.py` runs at the top of every `pN-check` and rewrites, from current behaviour:
`normalized/line1.json` (the runtime's own output, kept), every hash in the golden `pack.json`,
the resolved certificates, all eleven negative vectors and `index.json`; `keys-bootstrap.sh` then re-signs
the pack. A value regression in normalization that stays schema-valid rewrites `line1.json` and every
suite passes — *that file pins nothing*; the only value pin on normalized output is the dozen literals in
`TestGoldenSamplesEndToEnd`. The one comparison of regenerated against committed goldens is an `echo`
in `clean-clone-test.sh` that cannot fail. Frozen and compared by value: the two span maps, the specs,
the samples, the certificate snapshots. *Fixed:* `build_vectors.py --check` regenerates into a **scratch copy** and compares every file with the
committed one byte for byte (26 files; only the git-ignored, per-machine `pack.json.sig` is excluded), printing a
diff and failing on any difference; every phase check now calls `--check`; regeneration is `--write`, a deliberate
act whose diff is reviewed; with no argument the tool refuses. It could be fixed outright because the builder is
deterministic (fixed clock, sequential ids, fixed `resolved_at`): the first `--check` found **zero** differences,
so no decision about "intended differences" was needed. Proven on the defect it exists for: with the committed
`line1.json` altered to a schema-valid wrong `type_uid`, every suite used to pass; `--check` now fails and prints
the two lines. What remains true: `pack.json`'s hashes are still *derived* values (they must be) — the check pins
them to the committed bytes, so a change in the compiler's canonical form shows up as a reviewed diff, not silence.

**3.2 The subset guard compares two strings (Python side closed in the third pass; Go side open).** Both stacks compare `pack.table_hash` with
`index.json.table_hash`; neither recomputes the hash from `ocsf/pinned/<class>.json`. Delete leaf paths
from the table file and the guard, its negative vector and every suite still pass. *Third pass:*
`learning/tests/test_pinned_tables.py` recomputes each table's hash from its file with the generator's definition and
compares it with the file's own claim and the index; a table with a leaf path removed no longer matches. The Go
loader still compares two strings — the hash is over Python's canonical JSON, which plan §1 rules out reproducing;
redefining it over file bytes changes every pack hash. A team decision (P8 report §13.7). §3.3 and §3.5's `batch`
were assessed as not quick and are still owed, with the reason each is more than a test.

**3.3 Negative vectors satisfied by the wrong rejection (Open).** Three negatives
(`pack-mandatory-model-only`, `pack-structural-determination-two-survivors`,
`certificate-numeric-confidence`) are rejected by the *schema* before the semantic check they were written
for is reached, so those semantic checks (`validate.py` invariant-4, single-survivor, forbidden-keys) are
exercised by no vector. `reason_match` is any-of substring and includes `"schema"`, which prefixes every
schema error. Every pack negative also fails "spec_ref not found" because its `pack_dir` is `negative/`.

**3.4 Presence, count and shape instead of value (the replay half fixed in the second pass).**
*Fixed:* `runtime/internal/dsl/replay_values_test.go` — for ASA (302013, 302015, 302014/302016, 305011/305012),
PAN-OS (three files), FortiGate and Squid native, every value the spec extracts is compared, line by line, with
an **independent oracle** (a regex written against the message guide, `encoding/csv`, a separate key=value
scanner, `strings.Fields`): 1,650 ASA values, 14,594 PAN-OS cells, 532 FortiGate values, 1,100 Squid values; and
each case carries a **digest pin** over every (path, value) of every line, so any change in any extracted value
is a reviewed diff. No corpus text is committed — a digest reveals nothing of the Elastic-licensed fixtures. A
case with zero parsed lines fails. The first oracle for teardown messages was too narrow for one fixture line (a
bare user token after the port): the test failed loudly and the oracle was widened, not the line skipped.
`test_learn.py` differential 3 now asserts the line counts before `zip`. **Still open** in this family: 106023 /
106100 / 733100 have no value oracle (their optional tails make an independent regex as complex as the spec);
an oracle shares the *field layout* with the draft for PAN-OS (it checks the splitter, not the vendor's column
order); the items below. `mirror_test.go` checks that enum-typed properties are
strings and never compares the enum *values* with what Go accepts — the class of the `udp_datagram`
defect — and only `parser-spec` has a mirror test at all. `envelope_test.go` asserts `src_endpoint`
exists. `mixed_test.go` claims to check the evidence record's `source_id` and checks that
`ingest_channel` is non-nil. Propagation tests check slot indices and field names, never the attribute
each slot received.

**3.5 Emitted documents nobody validates (Open).** Span maps emitted by the Go engine and by `dslexec`
are compared with each other and never with `span-map.schema.json` (the sweep validated all 113
op-matrix maps by hand: 0 invalid — no live defect, no guard). Resolved certificates inside a promoted
pack are checked for *existence* by both loaders. **Lineage `batch` (normalized-event 1.3.0) has never
appeared in any emitted event in any test** — every de-batch test quarantines its elements; events
framed `udp_datagram` and `octet_count` are emitted in tests and demos and never validated. There is no
schema at all for gap records, checkpoints 1.1.0, export bundles, quarantine records, stats, the evidence
index, sessions, the propagation store or the spike recordings that `RecordedProvider` consumes as input.
P8's own addition is covered: `normalization@v2` events are validated against the contract by both stacks
(`TestCorrectionEmitsV2AndNeverTouchesV1`, step 7); the lake manifest has no schema (raised).

**3.6 Identity never checked (the model half fixed in the second pass).** *Fixed:* `assert_served_model`
(`learning/ulpf_learn/model/provider.py`), called by the CLI before any proposal is requested: the served file's
name (`/props`) must be the manifest's file for `--model-id`, and the GGUF header facts the server reports
(`n_params`, tensor `size`, `n_vocab`, `n_embd`) must equal the manifest's new `served_meta`; an unreachable
`/props` is a refusal, not "best effort". Tests: right model accepted; another model on the port refused by name;
the right name over different weights refused by header facts; a server reporting no facts refused; unreachable
refused. It ran for real inside the offline learning image. **Its limit, stated:** llama-server exposes no digest,
so a different file with the same name *and* the same four header facts would pass; the digest of the file on
disk is verified separately (`verified_model_hash`; pre-flight checks the copy the server mounts). The result is
recorded in the session's provenance, not in the pack — `provenance.proposal` is a closed object in the
parser-pack contract and was not changed. Still open: The `.sig`-names-a-different-authority branch of `pack.Load` is
unreachable from its test: the test edits `authority_id` without re-signing, so the signature check
fails first and `err != nil` passes — the branch has zero coverage. `checkAnchors` (P6) has no negative
test and no golden vector mentions anchors. Router and pipeline tests build `pack.Pack` in memory, so
the strings they use (`"active"`, `"template"`, `"46-105"`) are never held to the schema.

**3.7 Static checks by regex (partly fixed).** `TestStaticNoTryAllPath` reads two files and is defeated
by a method value, a wrapper, a loop with one intervening line. *Fixed:* it now also covers
`renormalize.go`, which P8 added and which legitimately holds the runtime's second `Program.Parse` call
(after `RouteChain`, once per event). P8's own `TestStaticNoRewritePath` has the same nature: it
constrains `lake.go` to two exclusive opens and no rewrite primitive, and says nothing about another
package writing the files directly — mitigated by checking that the only two callers never build a lake
path themselves.

**3.10 Two more, found while closing other things (both fixed).** (a) `scripts/build-learning-image.sh` waited
for readiness by grepping the container log for `server is listening`; the server prints `listening on
http://…`. The loop therefore always ran its full 180 s and fell through — and the script has no failure branch,
so "start check" could not fail. The new `p8-learning-image-check.sh` greps the real string and **fails** on
timeout; the old script's pattern is corrected. (b) `learning/Dockerfile` does `COPY keys keys` and
`.dockerignore` did not exclude `keys/dev/`, so the P4 learning image contained the dev **private** signing keys.
`keys/dev/` is now excluded from every build context (a first attempt also excluded `pack.json.sig`, which broke the container test stage — the golden pack's signature is what those tests load, and a signature is not a secret; p2-check caught it) and the check asserts the image
holds `keys/trust` only. The keys are demo-grade and regenerated per machine, and the image was never published;
it is recorded because "no private keys in git" (P5) was not the same as "no private keys in an artifact".

**3.8 Silent skips (fixed at the phase gate, open elsewhere).** Inventory: `replay_test.go:22` (corpus
absent → five tests; *always* inside the image), `pack_test.go:43` (`pack.json.sig` absent — git-ignored —
skips the only signature fail-closed test), `checkpoint_test.go:112` and `store_test.go:71` (any write
error skips the tamper test, not only the immutable flag), five `pytest.skip` on a missing runtime
binary or recording, `if corpus.exists():` with no else. `p8-check.sh` runs both suites verbosely and
**fails on any skip**, requires the corpus and Docker, and refuses `ULPF_SKIP_DOCKER`. P1–P7 checks still
pass with skips. P8's own tests contain one conditional assertion, stated in the test log: as root, the
lake's open-for-write refusal is not exercised (file modes do not bind root); the mode-bit assertion is.

**3.9 Measurements that include the instrument (Open).** The connection-flood heap bound is sampled once,
in a process that also holds every client connection; growth rises with client count (8 → 12 → 18 MiB at
3k → 10k → 16k) and the bound would eventually be crossed by the clients, not the server. Packages with no
tests at all: `keys` (the trust-store verifier), `normalize`, `mlfeat`, `spanmap`, and the three `cmd/`
mains — `ulpf-verify`'s fail-open lived in one of them.

## 4. What this audit does not claim

It is a reading of the checks, not a proof about the code: a masked assertion means the property is
*unverified*, not violated. Where a sweep could settle a question cheaply it did (113 span maps valid;
the five recordings' class equals the truth; four resolved certificates valid; all nine P7 named tests
exist). Three sweeps by a model and one verification pass by the same model is not an independent
review, and the list is long enough that something is surely missing. §3.1, §3.4 (replay values) and §3.6 (model identity), named here as the next three, were closed in the second
pass. The next three, in order: the **subset guard** that compares two strings and never rehashes the table
(§3.2); the **negative vectors** rejected by the schema before the semantic check they were written for (§3.3);
**lineage `batch`**, a 1.3.0 field that has still never appeared in an emitted, validated event (§3.5).
